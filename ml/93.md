### CampusX PDF notes - L93 Mathematics of SVM, hard margin (PDF pp. 2374-2388)

**1. Terms**

| term | meaning |
|---|---|
| hyperplane | the boundary that separates the classes |
| margin | the gap between the two boundary lines through the nearest points |
| support vectors | the nearest points; they define the margin |
| `w` | weight vector, **perpendicular** to the hyperplane, sets its direction |
| `b` | bias, shifts the hyperplane (`b = 0` passes through the origin) |

![PDF figure: optimal hyperplane, margin and support vectors](pdf_img/L93_p2376.png)

![PDF figure: weight vector, bias, margin planes and support vectors](pdf_img/L93_p2377.png)

**2. Deriving the decision rule**

Project a point `u` onto `w`. It is on the positive side when `w.u >= c` for some constant `c`. Rearranged, `w.u - c >= 0`; writing `b = -c`:

**`w.u + b >= 0` -> predict +1, otherwise -1**

**3. The three hyperplanes**

| plane | equation |
|---|---|
| positive margin | `w.x + b = +1` |
| decision boundary | `w.x + b = 0` |
| negative margin | `w.x + b = -1` |

**Why +1 and -1?** It is a scaling convention. `w` and `b` can be multiplied by any positive number without moving the boundary, so we choose the scale that puts the nearest points at exactly +1 and -1. Equal numbers on both sides give an equal margin.

**4. One constraint for both classes**

* for `y = +1`: `w.x + b >= 1`
* for `y = -1`: `w.x + b <= -1`

Multiplying by `y` merges them: **`y_i (w.x_i + b) >= 1`**, with equality exactly for the support vectors.

**5. Margin width**

Take a support vector `x2` on the positive plane and `x1` on the negative one. Project their difference on the unit normal `w / ||w||`:

`d = (x2 - x1) . w / ||w|| = [(1 - b) - (-1 - b)] / ||w|| =` **`2 / ||w||`**

A smaller `||w||` means a wider margin.

**6. Optimisation problem**

`maximise 2 / ||w||` subject to `y_i (w.x_i + b) >= 1` for all `i`

is the same as

**`minimise (1/2) ||w||^2` subject to `y_i (w.x_i + b) >= 1`**

The square removes the square root and the 1/2 tidies the derivative.

**7. Hard margin limits**

No point may violate the margin, so the data must be **perfectly linearly separable**. A single outlier can change the boundary a lot or make the problem unsolvable. The fix is the soft margin (L94).

**8. Worked example**

`w = (2, 3)`, `b = 3`, line `2x + 3y + 3 = 0`.

| point | `2x + 3y + 3` | class |
|---|---|---|
| (3, 2) | 15 | +1 |
| (-2, 0) | -1 | -1 (it lies on the negative margin) |

### CampusX PDF notes - L94 Soft Margin SVM (PDF pp. 2389-2400)

**1. Why hard margin is not enough**

Real data has noise and overlap. Hard margin then has **no solution**, is **very sensitive to outliers** and tends to overfit.

![PDF figure: basics of the hard margin SVM](pdf_img/L94_p2391.png)

(In this figure the lower label for the red squares should read class -1, not +1.)

![PDF figure: hard margin on ideal data versus its failure on real data](pdf_img/L94_p2392.png)

**2. The idea: allow some mistakes**

Each point gets a **slack variable** `zeta_i >= 0` (xi in many books), the amount by which it breaks its margin condition. Maximising `2 / ||w||` is turned into a minimisation:

**`minimise (1/2) ||w||^2 + C * sum of zeta_i`**

**subject to `y_i (w.x_i + b) >= 1 - zeta_i` and `zeta_i >= 0`**

Your note writes `||w||/2 + sum zeta_i`: that is the same idea with `C = 1`. The first part is the **margin error**, the second the **classification error** (your note: "SVM error is of two types").

**3. Reading zeta**

| `zeta_i` | where the point is |
|---|---|
| 0 | on or outside its margin line, correct |
| between 0 and 1 | inside the margin, still on the correct side |
| 1 | exactly on the decision boundary |
| above 1 | wrong side, misclassified |

`zeta` is measured from the point's **own margin line** (`w.x + b = y_i`), not from the decision boundary.

![PDF figure: soft margin objective and the meaning of the slack values](pdf_img/L94_p2394.png)

**4. The parameter C**

| C | penalty for violations | margin | risk |
|---|---|---|---|
| large | heavy | narrow, few errors | overfitting |
| small | light | wide, more errors | underfitting |

`C` acts like `1 / lambda`: stronger regularisation means smaller `C`. Start with `C = 1`, use small `C` for noisy data, and choose it by cross-validation.

**5. Hinge loss**

At the optimum each slack equals the **hinge loss**:

**`zeta_i = max(0, 1 - y_i (w.x_i + b))`**

| loss | formula | used by |
|---|---|---|
| hinge | `max(0, 1 - y f(x))` | SVM |
| log loss | `log(1 + e^(-y f(x)))` | logistic regression |
| squared hinge | `max(0, 1 - y f(x))^2` | squared-hinge SVM |
| 0-1 | 1 if the sign is wrong, else 0 | ideal but not convex |

**6. The dual problem (background for the kernel trick)**

With multipliers `a_i`, setting derivatives to zero gives `w = sum a_i y_i x_i`, `sum a_i y_i = 0` and `0 <= a_i <= C`. The dual is

`maximise sum a_i - (1/2) sum_i sum_j a_i a_j y_i y_j (x_i . x_j)`

Only dot products `x_i . x_j` appear. The upper bound `a_i <= C` is the one difference from the hard margin.

![PDF figure: soft margin SVM summary](pdf_img/L94_p2400.png)

### Code - L94 the effect of C

```python
import numpy as np
from sklearn.datasets import make_blobs
from sklearn.svm import SVC

X, y = make_blobs(n_samples=200, centers=2, cluster_std=2.0, random_state=0)   # overlapping classes

for C in [0.001, 0.1, 10, 1000]:
    clf = SVC(kernel='linear', C=C).fit(X, y)
    width = 2 / np.linalg.norm(clf.coef_[0])
    print(f'C={C:<6} margin width={width:.2f}  support vectors={len(clf.support_)}  accuracy={clf.score(X, y):.3f}')
```

(Run it: as `C` grows the margin gets narrower and fewer points are support vectors.)

### CampusX PDF notes - L95 Kernel Trick in SVM (PDF pp. 2401-2417)

**1. The problem**

A straight line cannot separate patterns such as one class in a circle inside another. A linear SVM gets only about **55 percent** on the concentric-circle data.

![PDF figure: the linear SVM - hyperplane, maximum margin and support vectors](pdf_img/L95_p2402.png)

**2. The idea**

Map the data to a **higher dimension** where a flat plane can separate it. Computing that mapping `phi(x)` can be expensive. The dual problem only needs **dot products** `x_i . x_j`, so we replace them with a **kernel**:

**`K(x_i, x_j) = phi(x_i) . phi(x_j)`**

The kernel gives the dot product in the high-dimensional space **without ever computing `phi`**. That is the "trick".

Prediction: `f(x) = sign( sum over support vectors of a_i y_i K(x_i, x) + b )`.

**3. Why it works: a degree-2 example**

For `x = (x1, x2)` and `z = (z1, z2)`:

`(x . z)^2 = (x1 z1 + x2 z2)^2 = x1^2 z1^2 + 2 x1 x2 z1 z2 + x2^2 z2^2`

which equals `phi(x) . phi(z)` with `phi(x) = (x1^2, sqrt(2) x1 x2, x2^2)`. One cheap square in 2-D equals a dot product in 3-D.

**4. The kernels**

| kernel | formula | space | use |
|---|---|---|---|
| linear | `x . z` | original | linearly separable, text, many features |
| polynomial | `(gamma x.z + c)^d` | finite | known polynomial interactions |
| RBF (Gaussian) | `exp(-gamma * distance(x, z)^2)`, `gamma = 1 / (2 sigma^2)` | **infinite** | the usual first choice for curved data |
| sigmoid | `tanh(a x.z + c)` | varies | rarely used, not always a valid kernel |

RBF: `K(x, x) = 1` and `K` falls to 0 as points move apart. It is infinite-dimensional because the Taylor series of `exp(2 gamma x.z)` has infinitely many terms.

A function is a valid kernel if the matrix of all `K(x_i, x_j)` is always positive semi-definite (**Mercer's condition**).

**5. Lifting the circles by hand**

Take `z = exp(-(x1^2 + x2^2))`.

| points | distance from centre | `z` |
|---|---|---|
| inner circle | about 0.1 | about 0.99, lifted high |
| outer ring | about 1.0 | about 0.37, stays low |

A flat plane at `z = 0.5` or so now separates them.

**6. Hyperparameters**

| parameter | kernels | low | high |
|---|---|---|---|
| `C` | all | wide margin, more errors | narrow margin, strict |
| `gamma` | RBF, poly, sigmoid | smooth boundary | wiggly boundary, local influence |
| `degree` | polynomial | simple curve | complex curve, overfits |
| `coef0` | poly, sigmoid | changes the weight of lower-order terms | |

**7. Practical advice**

Scale the features (kernels use distances); try linear first for high-dimensional data and RBF otherwise; tune `C`, `gamma` and `degree` with `GridSearchCV`; kernel SVM training grows roughly with `n^2` to `n^3`, so it is slow on very large data; set `probability=True` only if you need probabilities.

**Block 4 - a function to draw the decision boundary**

```python
zero_one_colourmap = ListedColormap(('blue', 'red'))

def plot_decision_boundary(X, y, clf):
    X_set, y_set = X, y
    # a fine grid over the whole plane
    X1, X2 = np.meshgrid(np.arange(start=X_set[:, 0].min() - 1, stop=X_set[:, 0].max() + 1, step=0.01),
                         np.arange(start=X_set[:, 1].min() - 1, stop=X_set[:, 1].max() + 1, step=0.01))
    # predict every grid point and colour the regions
    plt.contourf(X1, X2, clf.predict(np.array([X1.ravel(), X2.ravel()]).T).reshape(X1.shape),
                 alpha=0.75, cmap=zero_one_colourmap)
    plt.xlim(X1.min(), X1.max())
    plt.ylim(X2.min(), X2.max())
    # draw the points of each class on top
    for i, j in enumerate(np.unique(y_set)):
        plt.scatter(X_set[y_set == j, 0], X_set[y_set == j, 1],
                    color=zero_one_colourmap(i), label=j, edgecolors='k')
    plt.title('SVM Decision Boundary')
    plt.xlabel('X1')
    plt.ylabel('X2')
    plt.legend()
    return plt.show()

plot_decision_boundary(X, y, classifier)     # one straight line: it cannot work
```

### CampusX PDF notes - L97 Decision Trees: intuition, entropy, Gini, information gain (PDF pp. 1730-1773)

**1. What a decision tree is**

A tree of if/else questions. It is intuitive, interpretable, works with categorical and numerical data and assumes no data distribution.

| term | meaning |
|---|---|
| root node | the first question, no parent |
| decision (internal) node | a further question, has a parent and children |
| leaf node | final prediction, no children |
| splitting | dividing the data using a feature |
| branch / subtree | the path or part hanging below a node |
| depth | number of splits from the root to a node |
| purity | how uniform the classes in a node are |

![PDF figure: app recommendation tree - occupation first, then gender](pdf_img/L97_p1732.png)

**2. The tennis tree**

`Outlook` is the root. **Overcast** is always "yes". Under **sunny** the tree asks about `Humidity` (high -> no, normal -> yes). Under **rain** it asks about `Wind` (strong -> no, weak -> yes). Temperature is never used. (The tree drawn in the PDF labels some of these branches wrongly.)

**3. Geometric view**

Each split on a numerical feature is a line (plane, hyperplane) **parallel to an axis**. Together they cut the space into boxes (hypercubes), so simple splits can form a complex boundary.

![PDF figure: axis-parallel splits in two dimensions](pdf_img/L97_p1736.png)

(The vertical axis in this figure is labelled sepal length, but values from 0 to 4 are not iris sepal lengths. Read it as an illustration of the splits only.)

**4. How the tree is grown (pseudocode idea)**

1. if all rows have one class, make a leaf;
2. otherwise find the **best split**;
3. divide the data;
4. repeat on each part (recursive, greedy, top-down) until pure or a stopping rule applies.

**5. Advantages and disadvantages**

| advantages | disadvantages |
|---|---|
| easy to explain | overfits easily (high variance) |
| no feature scaling needed | small data changes can change the tree |
| prediction costs about `O(log n)` | weak on imbalanced data (can ignore the minority class) |
| selects features by itself | training cost is high for many numerical columns |

**CART** (Classification And Regression Trees) uses the same structure for both: classification leaves give the majority class and split on Gini or entropy; regression leaves give the mean and split on variance (MSE).

**6. Entropy**

A measure of disorder, impurity or uncertainty: **more knowledge, less entropy**. Ice has low entropy, water more, vapour the most.

**`E(S) = - sum over classes of p_i log2(p_i)`** (with `0 log 0 = 0`)

| dataset | counts | entropy |
|---|---|---|
| 2 yes, 3 no | mixed | 0.97 |
| 1 yes, 4 no | skewed | 0.72 |
| 0 yes, 5 no | pure | 0 |
| 2 yes, 3 no, 3 maybe | three classes | 1.56 |

* two classes: between 0 and 1, maximum at 50/50;
* `c` classes: maximum `log2(c)`;
* symmetric: `E(p) = E(1 - p)`;
* the log base only changes the unit (bits or nats), not the chosen split;
* for a continuous variable: a **narrow, peaked** distribution has low entropy, a **flat** one high entropy.

![PDF figure: entropy curve for two classes](pdf_img/L97_p1750.png)

**7. Information gain**

**`IG = E(parent) - sum over children of (rows in child / rows in parent) * E(child)`**

Tennis data, split on outlook:

| step | value |
|---|---|
| parent (9 yes, 5 no) | `E = 0.940` |
| sunny (2 yes, 3 no) | 0.971 |
| overcast (4 yes, 0 no) | 0 |
| rain (3 yes, 2 no) | 0.971 |
| weighted children | `5/14 * 0.971 + 4/14 * 0 + 5/14 * 0.971 = 0.694` |
| **information gain** | `0.940 - 0.694 =` **0.247** |

**Correction:** your slide (step 4) and the PDF compute `0.97 - 0.69 = 0.28`. They use 0.97 as the parent entropy, but step 1 shows it is **0.94**, so the gain is about **0.25**. Outlook still has the largest gain (humidity 0.152, wind 0.048, temperature 0.029), so the choice of root does not change.

The column with the **highest** gain is chosen, and the process repeats inside each child until the leaves have entropy 0.

**8. Gini impurity**

**`G = 1 - sum of p_i^2`**

| | entropy | Gini |
|---|---|---|
| range, two classes | 0 to 1 | 0 to 0.5 |
| pure node | 0 | 0 |
| 50/50 node | 1 | 0.5 |
| speed | slower (logarithm) | faster (squares) |
| scikit-learn | `criterion='entropy'` | `criterion='gini'` (default) |

Examples: 2 yes, 3 no gives `1 - 4/25 - 9/25 = 0.48`; 1 yes, 4 no gives `1 - 1/25 - 16/25 = 0.32`. (The PDF writes wrong counts next to these two results.) The two measures usually build very similar trees.

![PDF figure: entropy against Gini impurity with a worked example](pdf_img/L97_p1760.png)

![PDF figure: Gini impurity for a balanced and an unbalanced node](pdf_img/L97_p1761.png)

**9. Numerical columns**

1. sort the column;
2. try a split `f > v` at each value (scikit-learn uses midpoints between neighbouring values);
3. for every candidate compute the two children's weighted entropy and the gain;
4. keep the split with the **largest gain**, then recurse.

**10. Cost**

Training is expensive, because every feature and threshold is tried, but it happens once. Prediction only walks one path, about `O(log n)` for a balanced tree. (The PDF's `O(n^2 f log n)` is for a naive search; scikit-learn sorts once per node and updates counts, roughly `O(f n log n)` per level.)

**An everyday decision tree:** the game Akinator guesses a character through yes/no questions; `n` candidates need only about `log2(n)` questions.

**Block 1 - the measures**

```python
import numpy as np
import pandas as pd

def entropy(labels):
    p = pd.Series(labels).value_counts(normalize=True)    # class proportions
    return -(p * np.log2(p)).sum()

def gini(labels):
    p = pd.Series(labels).value_counts(normalize=True)
    return 1 - (p ** 2).sum()

print(round(entropy(['y'] * 2 + ['n'] * 3), 2), round(gini(['y'] * 2 + ['n'] * 3), 2))    # 0.97 0.48
print(round(entropy(['y'] * 1 + ['n'] * 4), 2), round(gini(['y'] * 1 + ['n'] * 4), 2))    # 0.72 0.32
```

```python
rows = """Sunny,Hot,High,Weak,No
Sunny,Hot,High,Strong,No

Rain,Cool,Normal,Strong,No

Sunny,Cool,Normal,Weak,Yes
Rain,Mild,Normal,Weak,Yes
Sunny,Mild,Normal,Strong,Yes
Overcast,Mild,High,Strong,Yes
Overcast,Hot,Normal,Weak,Yes
Rain,Mild,High,Strong,No"""

                  columns=['outlook', 'temp', 'humidity', 'wind', 'play'])
```

### CampusX PDF notes - L98 Decision Tree hyperparameters (PDF pp. 1774-1784)

**1. Overfitting and underfitting**

* **Overfitting:** very good on the **training** data, poor on new data. The tree keeps splitting until leaves hold a couple of rows, so it learns noise and outliers. (Your first bullet says "it overfits on the testing dataset"; it overfits the **training** set and does badly on the test set.)
* **Underfitting:** the tree is too simple (for example `max_depth=1`) and is poor on both sets.

![PDF figure: deep tree overfitting against shallow tree underfitting](pdf_img/L98_p1775.png)

![PDF figure: underfitting, balanced and overfitting decision boundaries](pdf_img/L98_p1777.png)

**2. The hyperparameters**

| hyperparameter | default | what it does | tree overfits when | tree underfits when |
|---|---|---|---|---|
| `max_depth` | None | maximum depth (**the most important**) | high / None | low |
| `criterion` | `gini` | split quality: `gini` or `entropy` | - | - |
| `splitter` | `best` | `best` threshold, or `random` thresholds | `best` | - |
| `min_samples_split` | 2 | rows needed to split a node | low | high |
| `min_samples_leaf` | 1 | rows required in every leaf | low | high |
| `max_features` | None | features examined at each split | all | very few |
| `max_leaf_nodes` | None | limit on leaves | high / None | low |
| `min_impurity_decrease` | 0.0 | a split must reduce impurity at least this much | low | high |

Two corrections to the PDF: its table shows the effect of `min_impurity_decrease` the wrong way round (its own text matches the table above), and `splitter='random'` picks **random thresholds** (the best of those), while choosing a random subset of features is the job of `max_features`.

**3. Notes on single parameters**

* `min_samples_split=50`: a node with 137 rows can split, one with 30 cannot.
* `max_features` as an int, a fraction, `'sqrt'` or `'log2'`; a new random subset is drawn at every node.
* `min_impurity_decrease` is compared with `(N_t / N) * (impurity - (N_right / N_t) * right_impurity - (N_left / N_t) * left_impurity)`.
* Newer scikit-learn also offers `ccp_alpha` for pruning after the tree is grown.

**4. Tuning**

Compare training and cross-validation accuracy.

| sign | action |
|---|---|
| both low (underfit) | raise `max_depth`, lower `min_samples_split` and `min_samples_leaf` |
| training high, test low (overfit) | lower `max_depth`, raise the minimums, limit leaves, prune |

Rough starting points: small data `max_depth` 3-5, medium 5-10, large 8-15; then search with cross-validation.

### How a regression tree chooses the split

**What it is looking for:** the threshold that makes the marks **inside each side as similar as possible**.

A leaf predicts the **mean** of its training rows, so the quality of a split is the error that this mean makes:

**`SSE = sum (y - mean of left side)^2 + sum (y - mean of right side)^2`**

(The same idea as `criterion='squared_error'`, the MSE weighted by the number of rows.)

**Procedure for one column (first diagram below)**

1. Sort the rows by the column (hours studied).
2. Place a threshold between two neighbouring values, for example `h < 3`.
3. Predict the mean of the left group and the mean of the right group.
4. Add up the squared errors of both groups.
5. Move the threshold to the next position and repeat.
6. Plot **error against threshold** (the small graph on the right of the first diagram) and take the threshold with the **lowest** error.

**With several columns (second and third diagrams):** do the whole search for **every** column. Each column gives its own best threshold and error, for example `SSE_hours` and `SSE_cgpa`. If `SSE_hours < SSE_cgpa`, the root splits on hours. In 3-D each split is a flat plane perpendicular to one axis.

**Then repeat inside each child** (recursion) until a stopping rule is met, such as "fewer than 4 rows in the node" or a maximum depth. Without a rule every row ends up in its own leaf and the tree overfits.

**Block 1 - the search, by hand**

```python
import numpy as np
import matplotlib.pyplot as plt

hours = np.array([0.5, 1, 1.5, 2, 2.5, 3.5, 4, 4.5, 5, 6, 6.5, 7, 7.5])
marks = np.array([20, 25, 28, 33, 36, 82, 86, 88, 85, 50, 46, 40, 38])

def sse(values):
    return ((values - values.mean()) ** 2).sum()

thresholds = (hours[:-1] + hours[1:]) / 2                    # midpoints between neighbours
errors = [sse(marks[hours < t]) + sse(marks[hours >= t]) for t in thresholds]

best = thresholds[int(np.argmin(errors))]
print('best threshold: hours <', best, ' SSE =', round(min(errors), 1))

fig, (a1, a2) = plt.subplots(1, 2, figsize=(11, 4))
a1.scatter(hours, marks); a1.axvline(best, color='red')
a1.set_xlabel('hours'); a1.set_ylabel('marks')
a2.plot(thresholds, errors, 'o-'); a2.axvline(best, color='red')
a2.set_xlabel('threshold'); a2.set_ylabel('total SSE')
plt.show()
```

### CampusX PDF notes - L99 Regression Trees (PDF pp. 1785-1796)

(The split search and the code are above, at your comments.)

**1. Overview**

A regression tree predicts a **number**. It splits the data on feature thresholds to reduce the squared error `SSE = sum (y - y_hat)^2`, and each leaf predicts the **mean** of its training rows: `y_leaf = (1 / n_leaf) * sum y_i`.

![PDF figure: example of a regression tree](pdf_img/L99_p1787.png)

(The numbers in this figure, such as "hours studied < 11.5", are illustrative and do not match the 0 to 7 hour plot on your board.)

**2. Why not linear regression?**

| | linear regression | regression tree |
|---|---|---|
| shape | straight line | steps (piecewise constant) |
| assumes | a linear relation | nothing about the shape |
| flexibility | low | high |
| extrapolation | possible | **impossible** beyond the training range |
| outlier sensitivity | high | lower for the inputs |

**3. Results quoted in the video (Boston data)**

| | value |
|---|---|
| `max_depth=5`, test R2 | 0.88 |
| grid search best cross-validation R2 | 0.645 |
| best parameters | mse, `max_depth=None`, `max_features=0.5`, `min_samples_split=0.25` |
| importance | RM 0.63, LSTAT 0.19, CRIM 0.07, DIS 0.07 |

The two R2 values are not directly comparable: one is a single test split, the other an average over cross-validation folds of a differently restricted model. (The PDF reads the gap as a sign of overfitting, which these numbers alone do not show.)

**4. Advantages and disadvantages**

| advantages | disadvantages |
|---|---|
| interpretable | overfits easily |
| little preprocessing | high variance |
| handles non-linear relations | step-like predictions |
| selects features | cannot extrapolate |

Control overfitting with `max_depth` (often 3-10), `min_samples_split`, `min_samples_leaf`, `max_leaf_nodes` and `min_impurity_decrease`.

```python
x = np.array([7.2, 3.6, 6.1, 2.5])               # the flower in your screenshot
print(viz_model.explain_prediction_path(x))      # the library's text version: the conditions used

def explain(model, x, feature_names, class_names):
    t = model.tree_
    node = 0
    while t.children_left[node] != -1:                       # until a leaf
        f, thr = t.feature[node], t.threshold[node]
        if x[f] <= thr:
            print(f'{feature_names[f]} is {x[f]}, which is at most {thr:.2f}, so go left')
            node = t.children_left[node]
        else:
            print(f'{feature_names[f]} is {x[f]}, which is more than {thr:.2f}, so go right')
            node = t.children_right[node]
    print('Reached a leaf. Prediction:', class_names[int(np.argmax(t.value[node]))])

explain(clas, x, iris.feature_names, iris.target_names)
```

**How to read it:** start at the root, check one condition at a time, and follow the branch that is true. The leaf you reach is the prediction. (`tree_` holds the fitted tree: `feature`, `threshold`, `children_left`, `children_right`, `value`.)

### CampusX PDF notes - L101 Introduction to Ensemble Learning (PDF pp. 1812-1848)

**1. Definition**

An **ensemble** combines several models into a stronger one. It rests on the **wisdom of the crowd**: the audience poll in KBC, thousands of product reviews, IMDb ratings, elections.

![PDF figure: wisdom of the crowd examples](pdf_img/L101_p1813.png)

**2. Prediction**

| task | combine by | formula |
|---|---|---|
| classification | majority vote | `y_hat = mode(h1(x), ..., hn(x))` |
| regression | mean | `y_hat = (1/n) * sum h_i(x)` |

Examples: votes 1, 0, 1, 0, 1 give class **1**; packages 8.1, 9.3, 7.5 and 8.8 lakhs give **8.425**.

![PDF figure: ensemble architecture for classification and regression](pdf_img/L101_p1815.png)

**3. The base models must be different**

Diversity comes from (1) different algorithms, (2) the same algorithm on different data, or (3) both.

**4. The four types**

| type | base models | data | combination | mainly reduces |
|---|---|---|---|---|
| **voting** | different algorithms | same | vote or mean | both a little |
| **stacking** | different algorithms | same | a **meta-model** learns how to combine them | both |
| **bagging** | same algorithm | bootstrap samples, trained **in parallel** | vote or mean | **variance** |
| **boosting** | weak models | trained **one after another**, focusing on earlier mistakes | weighted sum | **bias** |

![PDF figure: comparison of voting, stacking, bagging and boosting](pdf_img/L101_p1819.png)

* **Stacking:** the base predictions become the inputs of a meta-model: `y_hat = g(h1(x), h2(x), h3(x))`. In voting every model has the same weight; here the weights are learned.
* **Bagging** (bootstrap aggregating): from 1000 students draw several samples of 500 **with replacement**, train the same model on each. **Random forest** is bagging with decision trees plus random feature selection at every split.
* **Boosting:** after each model, raise the weight of the rows it got wrong so the next one concentrates on them (AdaBoost, gradient boosting, XGBoost).

![PDF figure: bagging process on student data](pdf_img/L101_p1824.png)

**5. Why it works**

* the decision boundaries of different models average out into a smoother one, as individual mistakes cancel;
* three independent classifiers at 70 percent: majority correct with probability `3(0.7^2)(0.3) + 0.7^3 = 0.784`;
* averaging `n` **independent** predictions divides the variance by `n`. Real models are correlated, so the gain is smaller.

**6. Benefits: bias, variance, robustness**

| base model | bias / variance | remedy |
|---|---|---|
| deep decision tree | low bias, high variance | bagging |
| linear / logistic regression | high bias, low variance | boosting |

An ensemble is also more robust to noise, outliers and shifts in the data.

![PDF figure: bias-variance trade-off and how ensembles balance it](pdf_img/L101_p1836.png)

**7. Costs and when to use**

More training and prediction time, more memory and less interpretability ("why was this loan rejected?" is easy for one tree and hard for 100). Boosting can overfit noisy data. Use ensembles when accuracy matters (production, competitions: the Netflix prize winner combined 107 models). Prefer a single model when speed, memory or explanation matter. Gains of a few percent are typical; an ensemble cannot replace good data and features.

### CampusX PDF notes - L102 Voting Ensemble: theory (PDF pp. 1849-1859)

**1. Process**

Train several **independent** base models (on the same or different data); for a query, collect all predictions and take the **majority vote** (classification) or the **mean** (regression).

![PDF figure: basic voting classifier](pdf_img/L102_p1850.png)

![PDF figure: training phase and prediction phase](pdf_img/L102_p1851.png)

![PDF figure: majority voting and averaging](pdf_img/L102_p1852.png)

**2. Why it works**

Different models make different mistakes, so strengths cover weaknesses.

![PDF figure: diversity, error compensation and collective wisdom](pdf_img/L102_p1853.png)

**3. The probability argument**

Three independent models, each 70 percent accurate. The vote is right when at least two are right:

| case | probability |
|---|---|
| all three correct | `0.7^3 = 0.343` |
| exactly two correct (3 ways) | `3 * 0.7^2 * 0.3 = 0.441` |
| **total** | **0.784** (your 78 percent) |

PDF example with unequal models (0.7, 0.6, 0.5): `0.21 + 0.21 + 0.14 + 0.09 = 0.65`. That beats the two weaker models but **not the best one (0.7)**, so voting is not guaranteed to beat every single model.

**4. Requirements**

| requirement | if violated |
|---|---|
| models are **diverse** (errors close to independent) | they fail together and voting adds nothing |
| each model is **better than random** (above 50 percent for two classes) | with three models at 30 percent the vote gets only 21.6 percent, worse than any of them |

![PDF figure: voting classifier mind map](pdf_img/L102_p1859.png)

### Code - L102 how accuracy grows with the number of independent models

```python
from math import comb

def majority_accuracy(p, n):
    """chance that more than half of n independent models, each correct with probability p, are right"""
    return sum(comb(n, k) * p**k * (1 - p)**(n - k) for k in range(n // 2 + 1, n + 1))

for n in [1, 3, 11, 51]:
    print(n, round(majority_accuracy(0.7, n), 4), round(majority_accuracy(0.3, n), 4))
# 1 0.7 0.3
# 3 0.784 0.216
# 11 0.9218 0.0782
# 51 0.9986 0.0014
```
